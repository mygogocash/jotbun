### Minor 1. The case pins the edge steps' order and job, but not that they run or can fail

- **Evidence:** mutants R1 (`continue-on-error: true` on the workers step), R2 (`if: ${{ false }}` on it) and R8 (`if: ${{ false }}` on the database job) each pass all 6 cases (`review-probe-R1.log`, `-R2.log`, `-R8.log`). So does the existing local-gate case.
- **Effect:** CI would stay green while the UserVault suites are skipped or their failures ignored. The case's name ("the edge steps run in the database job ...") and the commit title ("Pin where CI runs the Workers-runtime tests") claim more than this.
- **Cause:** a pre-existing limit of `workflowRuns`, which drops `if:` and `continue-on-error:` everywhere. The plan's Step 1 asks only for the order, so this is test strength, not a plan miss.
- **Verified fix:** one line at the end of the new case (`patched/scripts/ci/backend-workflow.test.mjs`):
  ```js
  assert.doesNotMatch(workflow, /^\s*(?:-\s+)?(?:if|continue-on-error):/m);
  ```
  - It kills R1, R2 and R8.
  - The RED, the control and W1 to W6 are unchanged (`fixprobe/pl.out`, `fixprobe/review.out`).
  - `backend.yml` has no `if:` or `continue-on-error:` today, and the P6C plan keeps `backend.yml` untouched.
- **Options:** add the line now (a 2-line follow-up), or carry it to P6C-T7, which next edits this file.
