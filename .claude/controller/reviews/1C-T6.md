## Focus items

### 1. Security of the fresh sign-in

- **Only after a fresh sign-in that went through.** `requestGlobalLogout` (`globalLogout.ts:40-45`), `requestAccountDeletion` (`deletion.ts:95-103`) and `requestExport` (`privacy.ts:94-102`) send nothing unless `freshSignIn()` answers `fresh`. `cancelled` gives `cancelled`; every other outcome gives `refused`/`denied` with `FRESH_SIGN_IN_FAILED`, or `reauth_required` for export. The loops in all three test files cover all six other outcomes. A resend (`submitGlobalLogout`, `submitDeletionRequest`, `retryExportRequest`) is reachable only from an `unconfirmed` state, which only a send produces. P12's narrowed `retryExportRequest` type makes a sign-in on resend impossible.
- **The new session's own credentials (R86).**
  - Deletion and export read `credentials()` once, after `fresh`.
  - The app passes the provider's `requestCredentials()`. It answers only while `active`, reads the token through `getAccessToken()` (which hands out a token only when its `sid` is the binding the read began with: `credentialProvider.ts:341-356`), and answers null if the epoch moved meanwhile (`:435-442`).
  - The port drops its cached JWT when a sign-in is accepted, so the first read after `freshFlow`'s `bootstrapped` mints a token for the new session.
  - The wiring probe confirms this end to end: the token's `sid` is the new binding.
  - Sign out everywhere goes over the port with the cookie, which the fresh sign-in replaced. The server's 300-second rule (plan Task 4, line 578) backs it.
- **`requestCredentials()` null.** It gives `reauth_required` with nothing sent (D2 and X3 killed). A rejection is not caught, and the screens show "Couldn't reach the sign-in service. Nothing ... Try again." (P2).
- **No purpose proof survives.**
  - A grep of `apps/app/src` and `apps/app/app` in both trees for `reauthentication|reauthenticate|ProofPurpose|GlobalLogoutProof|DeletionProof|ExportProof|createGlobalLogoutResources|global-logout|GlobalLogoutResult|fakeProof|\bProof\b` finds only `sessionEpoch.test.ts:228` (it pins the transport's `proof` option, as the receipt notes) and a wallet named `'Proof'` in `native-storage-proof.ts`.
  - `proof_id` remains only as R46's body field, a fresh UUID per request.
- **Nothing reuses a proof across sends.**
  - Each request draws two ids (D5 killed). Only a resend of the same request repeats them (M4 and X5 killed by the resend cases).
  - The screens record exactly the request handed over (P4). Their `seen` objects are local to each journey.
  - A second export draws a new command id (the existing "expired" render case).
- **Credentials on the wire (P13).**
  - Deletion and export send `Authorization: Bearer <fresh token>` and no `X-GoGoSpend-Session` (K13).
  - The receipt goes `tokenOnly` with the request's own token (M3 killed).
  - A request with its own credentials is never refreshed and never ends the shared session: `deletion.test.ts` "REAUTH_REQUIRED requests nothing more" asserts `ended` is empty.
  - Nothing new is logged: no `console`, `logFailure` or capture call is added anywhere in the diff.
