## Focus 3: the `__DEV__` define

`'true'` is right, and it cannot hide a production path a test used to run.
- **How Vitest applies it.** Vitest 4.1.12 removes a dot-free `define` key from Vite's config, `JSON.parse`s the value and sets it on `globalThis` in each worker. It does not replace source text (`vitest/dist/chunks/cli-api.B0Pz1_R7.js` lines 10137 to 10168, `setup-common.DYx3LtFI.js` lines 31 to 32). So the value is the boolean `true`, and a test can still set `globalThis.__DEV__ = false` itself. `catalogueRoute.render.test.tsx` does that for its release-build case, and it passes 3 of 3. `true` matches React Native's own Jest setup, and React's development build under `NODE_ENV=test`.
- **Nothing flips from false to true.** Before the define, any bare `__DEV__` read in the render suite threw `ReferenceError`. Of the installed packages, only `babel-plugin-react-compiler` and `@expo/fingerprint` read it as `typeof __DEV__` or `global.__DEV__`, and neither loads in a render test. The define therefore turns throws into the development branch and changes no branch a passing test took.
- **App code that reads it:**
  - `app/dev/catalogue.tsx` is tested both ways.
  - `src/api/sharedV1.ts:45` sets `allowLanHttp: __DEV__`. The 10 render suites that import `sharedV1` mock it, and the release value is held by the Node test `src/api/client.test.ts` lines 70 to 79, which this config does not run.
- **Sample with and without the define.** I made a copy of the config without the `define` line (`vitest.render.nodev.config.ts`, scratch only) and ran 8 suites both ways: `catalogueRoute`, `screenReader`, `SpendRoutes`, `SpendLayout`, `QuickAddScreen`, `SettingsScreen`, `PrivacyScreen` and `ImportRoute`. Both runs gave `Test Files 8 passed (8)`, `Tests 442 passed (442)`, with identical per-test results and no stderr (`sample-with-dev.log`, `sample-no-dev.log`).

### Minor

**m-1. The rejection branch's `heard` guard has no test (mutant X1 survives).**
`apps/app/src/wallet/motion/reducedMotion.tsx:28`: `() => { if (!heard) settle(false); },`. Changing it to `() => { settle(false); },` leaves all 8 wallet cases passing (`mutants-review.out`: `X1 SURVIVED ... Tests 8 passed (8)`). The planner's 16 mutants covered the twin guard on the resolve branch (M4) but not this one, so protocol step 5 has a survivor with no test. With the mutant, a phone that reports a change and then fails its first ask goes back to full motion, though the newer change said reduce. The code is correct; only the test is missing. A case like this kills the mutant. I ran it in scratch: it passes on `7ab140d` and fails under X1 with `expected 'reduced=false known=true' to be 'reduced=true known=true'`.
```tsx
test('a change heard before a failed answer is not overwritten by that failure', async () => {
  const phone = holdPhone();
  render(<WalletRoot><Probe /></WalletRoot>);
  act(() => { phone.change(true); });
  await act(async () => { phone.fail(new Error('no answer')); });
  expect(shown()).toBe('reduced=true known=true');
});
```
The path is rare (the ask has to reject, after a change), so I rank this minor. The controller can take it now or put it in the P2-T37 motion sweep.

**m-2. Installed phone builds stop launching once this merges, not only the wallet's gestures.**
`app/_layout.tsx` now imports `react-native-gesture-handler` on every platform. Gesture Handler 3.3.0 looks up its native module with `TurboModuleRegistry.getEnforcing('RNGestureHandlerModule')` (`src/specs/NativeRNGestureHandlerModule.ts:40`), and that call throws when the module is missing. Any iOS or Android build made before this commit therefore fails at launch.
The receipt's SKIPPED line says a client must be rebuilt "before a phone can run Reanimated, Worklets and Gesture Handler", which understates this. The plan requires the mount, so no code change is asked. The controller and owner should know that the next phone or simulator check (E2 screenshots included) needs `expo run:ios` / `run:android` first.
