**n2. When the same view registers again, `frameOf` answers at once with a measurement that landed while the view was away.** (frames lens L2-n2)
- **Where:** frames are kept per view in a `WeakMap` that `forget()` never clears (`cardFrames.tsx:38-39`, `:50-52`).
- **Probe FP4** (it reproduces in `synth/probes-shipped.log`):
  - The view leaves while a `measure()` is still on the way. That answer lands after it has left, and is correctly not given out.
  - The same host instance then registers again. `frameOf` answers that late value (2, 2) until the new measurement lands (3, 3).
- **Scope:**
  - "A measurement that lands after its view left is never given out" holds for a new view (FP2, FP3, FP6).
  - It does not hold when the same host instance re-attaches, as React does when it hides and shows a subtree (Suspense or Activity).
  - This happens only on the web, where `measureInWindow` answers after a `setTimeout` of 0. On a phone the answer is synchronous, so nothing lands late.
- **Fix:** `frames.delete(view)` in `forget()`.
- **Carrier:** a follow-up.

### 8. The test traps (P15)
