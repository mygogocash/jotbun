### Minor

**m1. The held line does not add up to the total when a wallet that is not a credit card is below zero beside a card that has spent.**
- **Where:** `walletsList.ts:35-36` puts a non-card balance below zero in the total only. `WalletsListScreen.tsx:185` shows the held line whenever `creditUsedMinor !== '0'`.
- **What the screen draws:** probe PC has a bank account at −฿1,000, a credit card at −฿500 and cash at ฿2,000. The screen draws the total `฿500` and the line `เงินที่มี ฿2,000 · หักบัตรเครดิตที่ใช้ไป ฿500`. That line reads as ฿1,500, so ฿1,000 goes unexplained.
- **Why it matters:** ruling P7 hides the line when no card has spent, because otherwise it "says more than the total without saying why". The same reason applies here, but the rule lets this case through. A cash wallet below zero is common in a diary when cash top-ups are not logged.
- **The plan:** each figure is exact and follows the plan's definitions ("held: every other positive balance"). So this is a display rule to settle, not wrong arithmetic.
- **Fix (either one):**
  - Show the line only when it reconciles: `BigInt(heldMinor) - BigInt(creditUsedMinor) === BigInt(totalMinor)`, which means no wallet that is not a card is below zero. Add PC as a case.
  - Or add this case to the receipt's E2-B differences (P17), so the owner decides.

**m2. No case holds the two order rules from `followups.md` #391 that the controller named: no effect seeds `setOrder` (n5), and `setOrder` runs once per press (n4).**
- **The code is right:** `ReorderTray.tsx` has no effect, and `move()` (`:56-62`) calls `void setOrder(next)` once.
- **The gap:** two of my mutants survive `WalletsList.render.test.tsx` (12 of 12 pass):
  - X1 adds `useEffect(() => { if (visible) void setOrder(shown.map(...)) }, [visible])`, the seed n5 warns about. Before the account's first read lands, it writes the by-name order over the person's kept order. Even after the read, it drops archived and unknown ids from the kept order on every opening.
  - X2 calls `setOrder` twice per press.
- **Fix:** add probe PA as a case. It keeps an order that also names an unknown id and an archived one, opens and closes the tray with no press, and expects no write to the order key and the stored text unchanged. Then it presses once and expects exactly one write, of the whole order shown. PA passes on the real code and kills X1 and X2.

**m3. No case holds ruling P10's "the route mounts no looks provider".**
- **The code is right:** `app/spend/wallets.tsx:10-13` wraps the list in `SpendV1Provider` only.
- **The gap:** X3 wraps the screen in a second `WalletLooksProvider` in the route, and it survives `WalletsList.render.test.tsx` and `PlanningRoutes.render.test.tsx` (16 of 16). The routes test mocks the screen, and the list's `?reorder=1` case writes to the same store either way.
- **Why it matters:** once P2-T18 mounts the provider in `WalletShell`, a second one in the route would keep its own memory. Home's provider reads only when the account changes, so Home's stack would miss a new order.
- **Fix:** add probe PB as a case in `WalletsList.render.test.tsx`. It mounts the route with `?reorder=1` beside a consumer of `useWalletLooks().order` under the harness's provider, presses ย้ายเงินสดขึ้น, and expects the consumer to see the new order. PB passes on the real code and kills X3.

### Nit

**n1. The by-name order of the wallets the kept order does not name is unpinned where `localeCompare` and code-point order differ.**
- **The code:** `walletsList.ts:56` sorts as the device diary does (`spendDiary.ts:105`, the same comparator).
- **The gap:** the Node case's names are ASCII and capitalised, so they sort the same either way. No render case pins the order of two or more unnamed wallets: the `?reorder=1` no-account check uses `arrayContaining`. So X7, a code-point comparison, survives the Node file (4 of 4) and the render file (12 of 12).

- **Fix:** add that pair, or probe PF, to the `frontFirst` case. PF kills X7.
- **Why it is worth pinning:** `homeWallets.ts` holds an identical copy (diffed) that P2-T24 replaces with this one, so the pin protects Home's stack too.
