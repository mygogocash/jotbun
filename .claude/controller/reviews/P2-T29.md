## Blockers

**B1. CI red: `test:unit` fails the repo's Hermes guard on `CategoryTray.tsx`.**
`CategoryTray.tsx:66-68` defines its own `newId()` as `globalThis.crypto?.randomUUID?.() ?? \`cat-${Date.now()}\``. `src/testing/hermesGlobals.test.ts:21` ("no app code reaches for the Web Crypto global, which Hermes lacks") fails in CI with `actual: ['wallet/categories/CategoryTray.tsx']` (job 130890039958: `test:unit` 1028 of 1029). I reproduced it locally: it fails on `cee7eff5` and passes on `2ff43b0e`. Hermes has no Web Crypto, so on a phone every new category gets the id `cat-<ms>`. The contract wants "a client-generated UUID" (`packages/contracts/src/v1/categories.ts:47`). Fix: use `newId` from `@mobile/screens/v1/parts` (expo-crypto), as `ThaiPackTray.tsx:17` already does.

**B2. CI red: five existing render files no longer load.**
CI's Render job (130890039714) has 1380 tests passing, but 5 of 118 files fail to load: `wallet/card/CardStack`, `wallet/looks/WalletLooks`, `wallet/privacy/PrivateMode`, `wallet/testing/walletHarness` and `wallet/tray/Tray` (`.render.test.tsx`). Each one throws `Cannot find module .../expo/build/async-require/hmr imported from .../setupHMR.js`.
- **The chain:** `dev/catalogue/wallet/index.ts` imports `categorySections.tsx`, which imports `WalletCategoriesScreen`, `ThaiPackTray` and `categoryCommands`. Those import `screens/v1/parts.tsx`, and `parts.tsx:5` imports `expo-crypto` at the top level. The five files import the wallet catalogue index and do not mock `expo-crypto`.
- **Reproduced:** `Tray` and `walletHarness` fail to load on `cee7eff5` and pass on `2ff43b0e` (36 tests). A copy of `Tray.render.test.tsx` that only adds `vi.mock('expo-crypto', ...)` passes all 27.
- **Who imports the index:** eight render files: the five above plus `Lock`, `AmountStep` and `WalletsList`, which already mock `expo-crypto`. The brief's gate ran none of them.

**B3. CI red: the screen-reader check fails, because the tray's text fields have no names.**
CI shard "ids of length 3n" (130890039962): 175 passed and 1 failed, `section bw-category-new: every control has a name`, on an unnamed textbox (placeholder `ชื่อหมวด`). **B4. Saving again after an unconfirmed save creates a second category (and pack items).**

Neither tray offers the hook's frozen `tryAgain`. Save and Add stay enabled while `commands.status === 'unconfirmed'`, and the hook's `send` only refuses while a send is running.

- **Probe P4** (the same for the pack): two "ทำบุญ" categories.

The test "a new category keeps its icon ..." does exactly this retry after a `network` failure, but never checks the id.

## Majors

**M1. Today's `CategoriesScreen` changed behaviour.** The plan says "no behaviour change" and "moved unchanged".
- **What changed:** after an unconfirmed or refused archive, the archive sheet now stays open over the footer's words and its Try again.
- **Cause:** today's `send` ran `setConfirming(false)` in every catch path. The moved hook drops it (`categoryCommands.ts:116-117`). The screen now closes the sheet only in `onConflict` and `onStateChanged` (`CategoriesScreen.tsx:91-106`).
- **Probes A1 and A2** (`probes/CategoriesArchiveProbe.render.test.tsx`; `archiveCategory` fails with `network`, or with `invalid`): both pass on `2ff43b0e` and both fail on `cee7eff5`, with `AssertionError: the archive sheet closes`. The 56 unchanged tests do not cover this.

**M2. The wallet screen never reads again after a tray saves.**
- **Cause:** `useLoad` reloads only on `reload` or `refresh` (`screens/v1/parts.tsx:236-253`). Both trays call `useCategoryCommands()` with no `onRefresh`, and the screen passes none.
- **Probe P5:** the new category is stored (1), but no tile appears.
- **Probe P6:** editing Pets twice sends version 1 both times (`[1,1]`). The person's own second change is refused with "หมวดหมู่นี้ถูกแก้ไขจากอุปกรณ์อื่น".
- **Knock-on:** the pack card and the pack tray keep offering items just added, which leads to more duplicates (B4).

**M3. A failed read is not told, and is shown as data** (checklist points 2 and 4).
- **What happens:** errors from `categories`, `budget` and `summary` fall back to `[]` or null (`WalletCategoriesScreen.tsx:58-72`). The screen then shows empty grids, ฿0 spent, ไม่จำกัด on every tile, and a pack card naming all nine C3 items. That card lets the person add categories they already have.
- **Probe P8:** with `categories` failing, there is no Try again, and the pack card shows "ส่งเงินให้ครอบครัว, ทำบุญ, เดลิเวอรี และอีก 6 หมวด".
- **Also:** there is no loading state. The screen reads `resources.categories()`, where every other category screen reads `ensureBuiltinCategories()`. Today's screen says the problem through `classifyLoadProblem` and offers Try again.

**M4. Coloured tiles are unreadable in dark mode** (checklist point 5; Global Constraints: 4.5:1 for text, 3:1 for graphics).
- **Cause:** `CategoryTile` uses `tileTint(category.color, false)` (`WalletCategoriesScreen.tsx:337`), which is the light tint, under `colors.ink` `#F4F2FA`.
- **Contrast** (`contrast.mjs`, all twelve hues): names and amounts 1.02 to 1.21:1; the quiet limit line 1.78 to 2.22:1; `over` 1.92 to 2.40:1. The kit's `WalletCategoryIcon` uses `tileTint(color, colors.isDark)` and gets 9.70 to 12.18:1.
- **Probe P13:** the dark Food tile is `rgba(251, 231, 213)`. Fix-probe F1 (that one argument changed) makes P13 pass.
- **Trays:** glyphs drawn in ink on raw hues are 1.15 to 2.96:1 in dark mode (`CategoryTray.tsx:221-222` and `296`, `ThaiPackTray.tsx:129-130`).

**M5. The seven swatches are named with raw keys.**
