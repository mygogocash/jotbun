## Findings

### Blocker

**B1. The `bw-deleted` section draws the screen with no fakes. Both catalogue-wide suites fail, and on a device the section crashes.**

- **Where:** `recordSections.tsx:7-21` renders `<Suspense fallback={null}><LazyDeleted /></Suspense>`.
- **Why it fails:**
  - `WalletDeletedScreen` reads `useSpendV1()` and `useDiaryView()` through `useRecentlyDeleted`, and nothing provides them.
  - `CatalogueScreen` adds no provider (`CatalogueScreen.tsx:240-256`). Only `screenSection`'s stage does (`screenSection.tsx:125-133`), which is how `recentlyDeletedSections.tsx` draws the old screen.
  - `useSpendV1` throws without a provider (`SpendV1Context.tsx:15`).
- **Probe 1, run twice:** the catalogue suite's own case (`CatalogueScreen.render.test.tsx -t "^section bw-(deleted|buttons) renders"`).
  - `bw-deleted` fails with `AssertionError: expected 0 to be greater than 0` at line 607: after `settle()` the section is still the empty fallback.
  - The control, `bw-buttons`, passes in the same run.
- **Probe 2:** `screenReader.render.test.tsx -t "section bw-deleted:"` fails with `AssertionError: bw-deleted en: a heading of its own: expected 0 to be greater than 0`.
- **Probe 3** (`probe-bw-deleted.json`):
  - Right after `settle()`, the section body has 0 children.
  - 3 s later the lazy import has resolved, and the page reports `Error: useSpendV1 needs a SpendV1Provider.`
  - There is no error boundary, so the whole catalogue is gone; the section element no longer exists.
  - On the simulator, the E2 deep link `section=bw-deleted` would show this error, not the board.
- **The rule:** R72 (plan line 97) says "Wallet sections use fakes only."
- **Why it was missed:**
  - The test that should have caught it, `WalletDeleted.render.test.tsx:303-308` ("is registered and renders"), never calls `render()`.
  - The brief's gate ran only the two kit neighbours.
- **P5 itself is right.** With a static import in place of `lazy()`, `walletHarness.render.test.tsx` and `Tray.render.test.tsx` both fail to load (`SyntaxError: Unexpected token 'typeof'`, mutant P5). So the fix must keep the screen behind `lazy()`.
- **Fix:**
  - Lazily load a module that builds the section the way `recentlyDeletedSections.tsx` does: a `screenSection` whose fake resources hold deleted records on `CATALOGUE_NOW`, whose script waits for a days-left line, and whose render is `<WalletDeletedScreen now={CATALOGUE_NOW} />`.
  - Give the `Suspense` a fallback that both suites wait on. They wait while `catalogue-screen-running` is shown (`CatalogueScreen.render.test.tsx:570-574`, `screenReader.render.test.tsx:42-48`), for example `<View testID="catalogue-screen-running" style={{ flex: 1 }} />`.
  - Make the "renders" test really render the section.
  - Add the two focused catalogue cases (`-t 'section bw-deleted'`) to the local gate.

### Major

**M1. Private mode leaks the amount after a restore (Review Focus 2).**

- **Cause:**
  - After a confirmed restore, the hook sets `notice` to `restoredText(row, locale, tc)` (`deletedData.ts:131`).
  - That text formats the amount (`historyModel.ts:207-209`: `'{entry} {amount} is back in History.'`).
  - `WalletDeletedScreen.tsx:272` draws the notice as it is, whatever `usePrivateMode()` says.
- **Probe** (`probe-private.json`), with private mode on, restoring rent:
  - Before the tap, neither `12,268` nor `182` is on screen.
  - After it, the container and its live region read `ค่าบิล ฿12,268.00 กลับมาอยู่ในประวัติแล้ว` (th) and `Bills ฿12,268.00 is back in History.` (en).
  - The notice is a live region, so a screen reader also speaks the amount.
- **Plan:**
  - Review Focus 2 (line 115): "no digit of an amount reaches the screen, a spoken label, the toast ...".
  - P2-T25 Step 1: "private mode hides every amount".
- **Tests:**
  - The private-mode test (`WalletDeleted.render.test.tsx:174-195`) never presses Restore.
  - The first test pins the amount in the notice (line 148), which is right only with private mode off.
- **Fix:**
  - Keep the old screen's words, since its suite pins them.
  - Let the wallet screen word a restore without the figure while hidden. For example, the hook could expose what was restored (the row, or a notice kind), so the wallet screen builds its own line.
  - Add the case: restore with private mode on, then check for no `฿` followed by a digit and no `12,268`, in the container and in every live region, in th and en.
