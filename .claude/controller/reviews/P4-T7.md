**m1. The list's keyset is never walked across a draft with no date or no time.**
- **Evidence:** the 120-draft case (`slip-drafts.test.ts:95`) ends pages at positions 50 and 100, and its limit-7 page at 7 (`:141-143`). Its seeding gives dates by `i % 5`, no date when `i % 10 = 9`, and no time when `i % 7 = 3`. At those positions every draft has both a date and a time: 09:30 on 2026-10-12, 08:30 on 2026-10-10 and 09:30 on 2026-10-14. No cursor in the file carries `d: null` or `t: null`.
- **Three mutants survive the whole file:**
  - M2 drops the cursor-side `coalesce(?, '')` (`drafts.ts:75`). A limit-1 walk shows 6 of 12 drafts, then ends the list with `next_cursor: null`. The rest silently go missing and would expire unconfirmed.
  - M3 refuses a cursor with `d: null` (`drafts.ts:59`). Page 8 answers 422 to a cursor the server itself issued.
  - M3b does the same for `t: null` (`drafts.ts:60`). Page 3 answers 422.
- **The code is right:** PR1 passes.
- **Fix:** lift PR1 into `slip-drafts.test.ts`.

**m2. Nothing pins that the confirm's digest covers each record's content (money path).**

### Nits

- **n1. The order comment is inaccurate.** `drafts.ts:34-35` says the order is "slip_drafts_order_idx read backwards".
  - EXPLAIN QUERY PLAN (PR8) shows otherwise: each page and each keyset scans every open draft and sorts them (`USE TEMP B-TREE FOR ORDER BY`), because the `coalesce(...)` expressions are not the indexed columns.
  - A plain `ORDER BY occurred_on DESC, occurred_time DESC, id DESC` reads the index with no sort, and SQLite already puts NULLs last in DESC.
  - Open drafts are bounded by the quotas (500 backfill uses in 30 days, 10 live reads a day, each draft gone after 30 days). So only the comment is wrong.
- **n2. The cursor puts a slip's date and time in the URL.** The query string is base64url JSON, readable by anyone who decodes it. `apps/edge/wrangler.jsonc:12` enables observability, so Workers Logs keep those values with each `GET /v1/drafts`.
  - The history cursor already does the same with record dates (`apps/api/src/history/cursor.ts:20`), so this follows house style.
  - No amount, name or account is in it. This is for the owner's awareness only.
- **n3. slipsDueAt reads every open draft after each write.** Its `min(expires_at)` (`prune.ts:53`) runs on every rearm, and there is no index on `slip_drafts (expires_at)`. The prune's two statements also scan.
  - The size is bounded as in n1. That keeps within the spirit of the alarm-hardening rule: `0004_alarm_bounds.sql` forbids due-time reads of every row a table has ever held, and drafts are deleted when they close.
  - If slip import ever raises its quotas, a later migration can add the index.

## Notes for later tasks

- **P4-T6 (`writeSlip`):**
  - Write `expires_at` with `toISOString()`, as the receipt says. The prune compares it as text (`prune.ts:34,36`), but `slipsDueAt` parses it (`prune.ts:56`).
    - Another format, such as `...00Z` without milliseconds or a `+07:00` offset, would leave a due draft unpruned while `slipsDueAt` stays at its time. The alarm would then refire at once on every run, because `rearm` floors a past due time to the clock.
    - A value that does not parse gives NaN, which reaches the schedule.
    - `exportsDueAt` has the same shape, and the schema has no CHECK on the column.
    - A case that a written draft's `expires_at` equals `new Date(expires_at).toISOString()` would pin it.
  - Write only contract times (`00:00` to `23:59`) and lower-case UUID draft ids. The schema's CHECK on `occurred_time` (`0006_slips.sql:28`) admits `24:00` to `29:59`, but the cursor decoder (`drafts.ts:60`) and `isSlipDraftsPage` refuse them. A page that ended at such a draft would give a cursor the next request refuses.
- **P4-T16a (review on the phone):**
  - A confirm's 409 `VERSION_CONFLICT` comes in two forms. Without `current`, a draft is gone: reload the list. With `current`, a record id is already used (PR5; ruling P4 leaves it unnamed): a reload would not help, but a new record id would.
  - Only the first refused record of a batch is named. For Review Focus 1 (a first backfill reaching before a wallet's start), check each draft's date against its wallet's `tracking_start` in the diary before sending. Otherwise the phone needs one round trip per refused draft.
  - A record holding a number that is not a safe integer is 422 `INVALID_COMMAND` on `payload`, before the records are checked (ruling P3).
