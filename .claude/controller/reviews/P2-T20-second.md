## Detailed Focus Verification

### 1. Exact Money Arithmetic
- **BigInt precision (`walletsList.ts:28-40`):** `walletsSummary` performs all minor-unit summations strictly using `BigInt` over canonical satang strings. An independent probe tested extreme values past 2^53 (e.g. 10^25 satang) confirming zero rounding error or precision loss.
- **Credit card debt isolation:** Spending on credit cards (`balance < 0n && kindOf(wallet.id) === 'credit_card'`) is accounted under `creditUsedMinor` (`creditUsed -= balance`) and deducted from `totalMinor`. Crucially, it is **never** counted in `heldMinor`. Planner mutant `S1` (counting credit card debt as held money) was executed under the heavy lock and killed by `walletsList.test.ts`.
- **Card paid ahead:** A credit card with positive balance (`balance > 0n`) is correctly accumulated into `heldMinor` (`held += balance`) and not in `creditUsedMinor`. Verified by planner mutant `S4`.
- **Summary card held line visibility (`WalletsListScreen.tsx:174-181`):** `{summary.creditUsedMinor === '0' ? null : ...}` ensures the held breakdown line (`wallets.held` / `wallets.creditUsed`) only displays once a credit card has active spending. Mutants `L4` and `L5` confirmed this behavior.

### 2. Private Mode & Data Isolation
- **Screen and Label Masking:** In `WalletsListScreen.tsx`, `WalletRow` resolves `amount` as `hidden ? t('common.amountHidden') : spokenMoney(...)`. When private mode is active, row accessibility labels output `... ยอด ซ่อนยอดเงินอยู่` or `... ใช้ไป ซ่อนยอดเงินอยู่`.
- **Component Masking:** Total, held, and credit-used amounts in `SummaryCard` render through `WalletAmount`, which natively displays `฿••••` and outputs `common.amountHidden` to screen readers.
- **Archived List:** Rows in `ArchivedWallets` render only the wallet name and kind line; they expose no balance digits or amounts.
- **DOM & Attribute Leak Audit:** An independent render probe verified that under private mode, not a single digit of any wallet balance appears anywhere across `textContent` or element attributes (such as `aria-label`). Planner mutant `L8` was rerun and killed.

### 3. Writes & State Management
- **Reorder (`ReorderTray.tsx:43-57`):**
  - Reordering is completely disabled and unmounted when `accountId === null` (`WalletsListScreen.tsx:75, 96, 107`).
  - Each button press invokes `setOrder(next)` with a freshly allocated array (`moveWallet`).
  - Synchronous ref tracking (`made.current`) ensures that consecutive rapid presses before React re-renders correctly chain moves without dropping state or reverting to stale UI. Planner mutants `T1` (order saved last-first) and `T3` (ignoring `made.current` ref) were rerun and killed.
- **Unarchive (`WalletsListScreen.tsx:288-323`):**
  - Unarchive calls are guarded by `sending.current = true` in a `useRef`, preventing duplicate command dispatches on rapid double clicks.
  - Buttons are disabled while in flight (`held = phase === 'saving' || phase === 'unconfirmed'`).
  - The "Try again" action for unconfirmed commands invokes `unarchive(walletId, version)` with the identical slot and version, preserving the idempotency key generated by `useCommandKeys`. Planner mutants `L14` and `L18` were rerun and killed.
- **Catalogue Isolation (`walletListSections.tsx:24, 49-57`):**
  - Catalogue sections write looks and order exclusively to dedicated mock account `0000000c-0000-4000-8000-00000000ca7a`.
  - Assertions confirm the real user's test account store is never touched during catalogue test execution.
