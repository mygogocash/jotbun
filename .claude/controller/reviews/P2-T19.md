### Major

### Minor

**m1. The hook can send `wallet_added` twice for one wallet.** `walletCommands.ts:50-61` has no in-flight hold (C1), and the own-create branch (`:64-68`) emits for any create whose id exists.
- R7: two presses on one probe button before a re-render. Both sends use the same key, the second replays the first's acknowledgement, both answer `done`, the fake holds one Jar, and `wallet_added` is sent **2** times. That is a resend of an already acknowledged key reporting again.
- R8: the same create sent again after `done` (new key, own create): `done` twice, and **2** events.
- The hook test does exactly R8 at `walletCommands.render.test.tsx:277-281` ("the same create again is a new command") and stops before counting `added(sent)`, which is 2 there.
- Not reachable from today's pages: their ref guard, and the form's `saving` phase until it unmounts. But the receipt's note to P2-T20 says to hold presses "while `sending` is true". `sending` is React state, which a second tap in the same frame does not see.
- Suggested fix (small), either:
  - the hook reports each wallet id once (a `useRef(new Set<string>())` checked before both `trackWalletAdded` calls), plus `expect(added(sent)).toHaveLength(1)` after line 278; or
  - at least, P2-T20's and P2-T21's briefs require a ref guard like the pages', and the receipt note is corrected.

**m2. The emitter runs inside the save's `try` (`walletCommands.ts:60`) and inside its `catch` (`:67`).** If emitting throws, an acknowledged create is read as a failure.
- R11, with the tests-only `setConsentedTelemetrySink` throwing: the wallet exists (fake holds 3), but the form shows "This entry could not be saved." with Create enabled. Pressing Create again sends a second create (own create), whose emit throws inside `catch`. `send` rejects (Vitest: "Unhandled Rejection: Error: sink … at Object.send walletCommands.ts:67"), and the form stays on "Saving…" for good.
- Latent today: `getAnalytics()` is null in production until 1D-T6, and `cleanEvent` is pure. After 1D-T6 it rests on `client.capture` never throwing.
- C8's own reasoning (follow-ups run after the hook answers, so one that throws is not read as a failed save) applies to the emitter as well.
- Suggested: decide the outcome first and emit after the `try`/`catch` (or guard the emit). If left, record it as a follow-up for 1D-T6.

**m3. The no-look path that today's screen takes is not pinned.**
- A3 (own create emits only with a look) and A11 (the form sends a made-up look) both survive 95/95.
- The only own-create event test passes `LOOK` (line 252), and no page test installs `recordAnalytics()`. So dropping today's screen's event on a Try again that meets its own wallet, or sending a fabricated `wallet_type`, would pass.
- The code is right (R1 to R6). This task is the one that turns the event on for today's screen.
- One page pin in the file's "pages' own answers" section kills both: R3 through the screen, asserting `sent` equals `[{ kind: 'capture', name: 'wallet_added', properties: { origin: 'app' } }]`. 1D-T7's later `WalletsScreen.render.test.tsx` case does not cover the own-create path.

**m4. Two hook rules that only the Bun Wallet screens will use are unpinned.**
- A4: `sending` cleared only on `done`. After any refusal or unconfirmed answer `sending` would stay true, and a P2-T20/T21 that holds presses on it would freeze. The one `sending` test only checks a `done`. My R9 (refusal then unconfirmed, `sending false` after each) kills it.
- A7: a second unconfirmed command keeps the first in `pending`, so `resend()` would resend the older command. Not reachable from the pages, which resend their own `pending`.
- Both are plan interface (`sending`, `resend()`). A test each closes them, here or as a carried note to P2-T20.

### Nit

1. A1 and A2: the pages' in-flight guards (C1) have no test. They are verbatim from before and covered in practice by the busy button and the phase check. No action.
2. A6: the freeze applies to a refusal before processing of any command while another is pending (the old rule). Unreachable from the pages (the form is locked, other list rows are disabled). A comment in the hook would help P2-T20.
3. `added()` (`walletCommands.render.test.tsx:94-97`) drops `origin` without checking it. R1 shows it is exactly `'app'`. Optional.
4. E5's fallback (`WalletsScreen.tsx:261`) is dead by C3. Accepted call. The comment says so.
