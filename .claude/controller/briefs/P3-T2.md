## Planner rulings (the calls this brief makes, with the reason for each)

- **P1. Non-rebuilding migration `0005_transaction_source.sql`.**
  Adding `source` to `transactions` uses `ALTER TABLE transactions ADD COLUMN source TEXT CHECK (source IN ('typed', 'photo', 'slip_import', 'tell_bun', 'statement', 'share_extension', 'siri'))`. We never rebuild `transactions`: a rebuild's table drop would fire child foreign key actions, deleting all receipt links (`transaction_attachments` has `ON DELETE CASCADE`) and setting import links null (`import_row_progress` has `ON DELETE SET NULL`). `ALTER TABLE ADD COLUMN` is in-place, preserving every row and link.
- **P2. Migration numbering and ordering (P5-T4 review 7-step checklist).**
  The migration is numbered `0005_transaction_source.sql` with idx 5, tag `'0005_transaction_source'`, and `when: 1761782400000`, strictly greater than `0004_alarm_bounds`'s `when: 1761696000000`.
- **P3. Carry followups from P5-T4 review (`currency-migration.test.ts`).**
  Three followups are addressed in `currency-migration.test.ts`:
  1. "every table that references wallets keeps its rows" compares only tables that existed before the rebuild (`expect(references()).toEqual(expect.arrayContaining(before))` and `expect(held(before)).toEqual(was)`), and asserts that unseeded referencing tables fail.
  2. Asserts that every FK referencing wallets has `on_delete === 'NO ACTION'` before and after migration.
  3. The exact-row test only compares 1A columns and P5 currency columns (`RECORD_1A_COLUMNS` and `RECORD_MONEY_COLUMNS`), leaving out future columns like `source`.
- **P4. Probes C1 to C4 verified.**
  - C1: Stand-in unseeded table fails the unseeded assertion.
  - C2: Stand-in later referencing table passes the updated referencing-table case.
  - C3: M24 mutant (unseeded table before rebuild) is caught.
  - C4: Stand-in later referencing table fails the old head's referencing-table test (proving the head would have failed, mutD).
- **P5. Shared file `events.ts`.**
  Additive edit: `export type RecordSource = import('@gogospend/contracts').TransactionSource;` replacing `'typed' | 'tell_bun'`. Kept as a clean one-line replacement with no reordering.
- **P6. `createTransaction` vs `updateTransaction`.**
  `source` is provided only at creation time; it cannot be modified by edit (`PATCH /v1/transactions/:id`). A `PATCH` payload with `source` is rejected with 422 `UNKNOWN_FIELD`.
- **P7. Idempotency and digest.**
  `source` is included in the digested command payload only when present. A create without `source` digests identically to pre-P3 payloads, ensuring compatibility with replays of in-flight commands.
- **P8. Version bump to 0.2.0.**
  `apps/app/app.json` has `expo.version` bumped from `0.1.0` to `0.2.0`, satisfying `AI_MIN_CLIENT_VERSION = '0.2.0'` in contracts, verified by `aiClientVersion.test.ts`.
- **P9. Routes render tests verified.**
