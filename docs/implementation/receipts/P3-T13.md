  - **The review, once (P7).** Saved: `onSaved` takes the pending review (clears it) before sending `savedOutcome(original, draftFieldsOf(saved.draft, saved.draft.amountMinor))`, so a second `onSaved` sends nothing more. Dropped: when the tray closes unsaved (an effect on `visible`), or when a new AI draft or the sheet's draft replaces it, with `fieldsEdited: 0`. A host that goes away sends nothing.
  - **The review's original (P6).** The entry as the tray shows it after the fill, with the amount Save would settle on. At save the review compares `draftFieldsOf(saved.draft, saved.draft.amountMinor)`: the same settled amount.
  - **No draft over a save in flight (P8).** `applyAi` returns while `useEntrySave` locks the entry (saving, unconfirmed or conflict).
  - **m1.** The tally call in `reviewDraft` sits in `try`/`catch`, so a tally that throws at once never fails a review. `reviewDraft` stays synchronous.
  - **Analytics (P11).** `record_saved` carries `source` and `has_photo`. `ai_draft_reviewed` carries only `outcome`, `fields_edited`, `model` and `escalated`: the tray test reads it through `reviews()` (which removes only `origin` and the common rule properties) and compares it with `reviewOf(...)` by exact equality, so an extra field would fail.
