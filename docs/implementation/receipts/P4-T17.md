- **What changed:**
  - **Registration** (`pushRegistration.ts`). No project id answers `no_project` (none until D33). A signed-out phone answers `not_allowed` and reads nothing. The permission is read, never asked: anything but granted sends nothing. Only then is the token fetched. The record (`push-device`: token, platform, language, slip-notice switch, the session's hash, and the time) is written only after the server answers. A record is current for a week (`PUSH_RENEW_MS`). A damaged record, one dated after now, or one whose time is not a number counts as none. Thai goes as `th`; English and Vietnamese go as `en`. A failure answers `failed`, keeps no record and never throws.
  - **The session.** The phone keeps `sessionHash(binding)`, the lowercase hex SHA-256 of the binding's UTF-8 through `expoSha256`. The request body is the contract's four fields (`push_token`, `platform`, `language`, `slip_notices`) and carries no session. The binding is never stored.
  - **The host** (`PushHost.tsx`). It registers at mount, after each session change that changes the binding, and after a language change, one run at a time. The shared slip client is reached only when a registration is sent. It sets the app's only notification handler: `slips_ready` shows in the list only; the other three kinds show a banner and go to the list; none plays a sound or sets a badge; anything that is not push data shows nothing. For taps, it adds the listener first, then reads `getLastNotificationResponse()`. Each response is taken once, by its identifier. The route waits while `useLockCover().hidden` is true, goes once with `router.push`, and is then cleared with `clearLastNotificationResponse()`. A tap whose data is not a push opens nothing.
  - **Routing** (`pushRouting.ts`). `slips_ready` to `SLIP_REVIEW_HREF`; `statement_parsed` to `/spend/import`; `export_ready` to `/settings/privacy`; `month_recap_ready` to `{ pathname: '/spend/recap/[month]', params: { month } }`. Anything that is not push data opens nothing.
  - **The permission hook** (`notificationPermission.ts`). `useNotificationPermission()` reads the phone's answer at mount and again when the app becomes active. `ask()` is the only place this task requests the permission. `openSettings()` is best effort, through expo-linking. Off the phone the answer is `denied` and nothing is asked.
  - **The modules** `expo-notifications` and `expo-constants` load once for the app's life (P9).
