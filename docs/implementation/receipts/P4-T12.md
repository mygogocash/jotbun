- **What it does:** the phone's slip core, for P4-T13 to P4-T22.
  - `slipResources.ts`: the ten slip calls over the v1 transport, each answer checked against its contract DTO. The slip batch goes as its JSON's bytes typed `application/octet-stream`, so `POST /v1/slips` reads it from its stream (P4-T6); it waits 90 seconds and is never resent by the transport. Confirm and dismiss are commands acknowledged for the `slip_inbox` entity; the account update carries If-Match under a new command id; slip refs and devices are plain writes answering 204.
  - `slipRefs.ts`: each account's salt in SecureStore (`WHEN_UNLOCKED_THIS_DEVICE_ONLY`, in the given access group), fetched once, kept and held in memory, and the salted hash of a slip QR's normalized reference, the contract's vector. A reference that cannot be normalized gives no hash and asks for no salt.
  - `getSharedSlipResources()` over the one shared transport, so every slip call carries `X-GoGoSpend-Analytics: off` unless this phone's answer is yes (1D-T6's m4).
  - The sign-out erase forgets the account's salt on iOS and Android; a keychain that refuses never stops it.
  - `slipRoutes.ts`'s four typed links and the ten slip routes, each a redirect to `/spend` until its screen task.
  - `fakeSlipResources`, the fake slip server later tasks drive: it refuses as the server will (slip import closed, a gone draft, a stale or unknown account).
