### What the vault serves

The 29 routes phase 1A ported, each with the PostgreSQL route table's access, gates and status (`test/vault-route-coverage.test.ts`):
- The front door (Task 2): `GET /v1/policies` (public; the Worker answers it from `config:v1`), `GET /v1/me`, `POST /v1/me/logout`, `POST /v1/me/policy-acceptances`, `PUT /v1/me/privacy-preferences`.
- Wallets and command status (Task 3): `GET /v1/wallets`, `GET /v1/wallets/:id`, `POST /v1/wallets`, `PATCH /v1/wallets/:id`, `POST /v1/wallets/:id/archive`, `POST /v1/wallets/:id/unarchive`, `POST /v1/commands/status`.
- Categories (Task 4): `GET /v1/categories`, `POST /v1/categories/builtins`, `POST /v1/categories`, `PATCH /v1/categories/:id`, `POST /v1/categories/:id/archive`, `POST /v1/categories/:id/unarchive`.
- Transactions (Task 5): `GET /v1/transactions/:id`, `POST /v1/transactions`, `PATCH /v1/transactions/:id`, `DELETE /v1/transactions/:id`, `POST /v1/transactions/:id/restore`.
- Budgets (Task 6): `GET /v1/budgets/:month`, `PUT /v1/budgets/:month`.
- History and the summary (Task 7): `GET /v1/history`, `GET /v1/history/deleted`, `GET /v1/summary`.
- Sync (Task 8a): `GET /v1/sync/changes`.

Behind them:
- Each person's vault is `env.VAULT.idFromName(sub)` of the verified token, opened with `locationHint: 'apac'`. No route reads a user or vault id from the request.
- Tokens are checked with jose against a JWKS: EdDSA or RS256, a lifetime of at most 900 seconds, `sub` and `sid` UUIDs.
- `config:v1` in KV carries the policies, gates and client minimums. An unreadable or malformed value pauses every gate (fail closed); an absent one leaves the gates open and the policies unpublished.
- Rate budgets are counted in the vault's memory (plan call P4).
- Each command is one `transactionSync` block with the API's seven steps, on a schema the vault migrates on wake.
- Retention runs on the vault's alarm (Task 8b): deleted records are purged after 30 days, superseded changes are pruned and an older cursor gets `410 RESYNC_REQUIRED`, and receipt digests are dropped after 30 days while the receipts stay.

At the 1A-T9 merge (`e893255`) the vault's table held 30 ported routes (1A's 29, and 1B-T3's `GET /v1/bridge/gogocash/catalogue`), 0 pending, 27 deferred and 6 retired: all 63 routes the PostgreSQL edge declares. 1D-T10 had added `GET /v1/sync/live`, which the PostgreSQL edge never had.
