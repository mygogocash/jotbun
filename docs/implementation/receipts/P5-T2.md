- **Release (C5, X20; asked by P3-T2's review): `CURRENCY_MIN_CLIENT_VERSION` is `0.3.0`, and the owner action is P6C's.**
  - Builds 0.1.0 and 0.2.0 check wallets, categories, records and totals with exact-key validators (`isWalletSnapshot`, `isCategorySnapshot`, `isTransactionSnapshot`, the app's `isTotals`).
  - So before any server sends a phase 5 key (a wallet's look or a currency other than THB, a category's `icon` or `pack_key`, a record's money keys, totals' `currency`), raise the server's minimum client versions to at least `0.3.0`: `config:v1`'s `client_versions`, or `MIN_CLIENT_VERSION_IOS` and `MIN_CLIENT_VERSION_ANDROID`. One such key fails a whole history or sync page on an older build (`diaryRepository.ts`: "A change group does not match the sync contract."), and that device stops syncing, a second device of the same account too.
  - Nothing sends them yet. The vault sends wallets' and categories' new keys from P5-T5, and records' and totals' from P5-T10 and P5-T11.
  - In the other direction, no build sends the new request keys yet: looks from P5-T19, money from P5-T21 on. A vault older than P5-T5 or P5-T10 answers them with 422 `UNKNOWN_FIELD`, so the vault ships before the build that sends them.
  - `/v1/me`'s `home_currency` is safe for older builds: the app reads only `pending_policies` there (`apps/app/src/spend/v1/policies.ts`).
